## Расположение

```text
AGENTS.md                        # обязательные правила Developer / Reviewer
README.md                        # навигация и статус
docs/spec/SPEC.md               # единый источник REQ, AC, состояний и приёмки
docs/spec/ARCHITECTURE.md       # архитектура, AD/CON и доверенные границы
```

`SPEC.md` содержит 62 REQ/ERR, 85 уникальных AC и полную матрицу трассируемости §18. Методы Т/И/Д/А менять нельзя. Архитектура имеет единственный нормативный источник — `ARCHITECTURE.md`; `DATA_MODEL.md` и `SECURITY.md` не добавляют отдельных правил.

## Как использовать

1. **Основания утверждения:** v0.12 прошла docs-only проверку, затем полный independent review выявил начальный bootstrap deadlock; в v0.13 он исправлен. Заключительный независимый re-review `AIO_v0.13_INDEPENDENT_RE_REVIEW(1).md` 27.10.2026 — `APPROVED`, 0 материальных блокеров, затем владелец отдельно утвердил exact v0.13 ZIP. Окончательное решение и его область записаны в SPEC §0.0.1 как APR-08.
2. **После КТ4:** нормативная версия v0.13 утверждена, но запуск разработки и внешние Git-записи требуют собственных проверок среды, полномочий и обязательных gates. Отдельное owner approval обязательно для merge/deploy/production. OQ-09/A и OQ-10/A остаются APR-06/07.
3. До первого запуска разработчика / интеграции выполнить pre-deploy зависимости DEP-01…05 и реальные проверки, определить точные pins, проверить sandbox и права. До этого результат `NOT_CHECKED`, не PASS.
4. По утверждённому ТЗ работа идёт по P01–P07, начиная с security-first P01/P02; отчёты Developer/Reviewer привязывать к exact SHA и AC. До реализации C-08/C-09 начальное подтверждение owner AC-N-SEC-05.3 проводится **вручную** через аутентифицированный GitHub PR review с точным SHA/manifest/permissions по ARCH §4.6; нет настоящего PASS — нет `COMPLETED` P01 и старта P02. Runtime approval и production inspection остаются отдельными обязательными проверками.

**При помещении в существующий репозиторий:** если в корне уже есть `AGENTS.md`, **не перезаписывайте** его автоматически. Нужно согласовать правила и приоритеты согласно СТ-ТЗ v2.8; конфликт — отдельное решение владельца. Внешний GitHub-репозиторий здесь не изменялся.

Для публичного репозитория дополнительно проверьте, что допустимо раскрыть структуру угроз, *имена* переменных credentials и краткий журнал решений в `SPEC.md` (значения секретов включать запрещено).

Предыдущие changelog, журналы авторского self-audit, архивы независимых проверок и временные verification-файлы сознательно **не включены** в этот рабочий комплект. Нормативный журнал APR-01…08 и актуальная история SPEC сохранены. Отчёт независимого Reviewer можно хранить отдельно от repo-ready комплекта.
